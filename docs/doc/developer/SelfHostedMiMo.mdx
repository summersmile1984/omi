---
title: "Server OS with Xiaomi MiMo"
description: "Select hosted chat and speech while retaining local embedding and storage."
---

Render `self_hosted.local` with `--operator-ai mimo-cn` to select Xiaomi China
Token Plan for chat, business extraction, ASR and TTS. The model identities are
`mimo-v2.5`, `mimo-v2.5-asr` and `mimo-v2.5-tts`. BGE-M3 embedding and the existing
PostgreSQL, Redis, MinIO, Qdrant and Typesense services remain local.

Run `deploy/self-host/ci/product.py` with a new private `--output` directory,
`--embedding-store` and `--mimo-secret-file`. The private JSON contains
`MIMO_API_KEY` and `MIMO_BASE_URL`; the latter must be
`https://token-plan-cn.xiaomimimo.com/v1`. Do not supply the local LLM or speech
model stores in this mode. Keep the credential file outside the source tree.

All three providers use Chat Completions. Live recording submits bounded audio
windows and preserves the existing transcript, finalization and memory owners.
It provides chunked recognition and a single anonymous speaker, not native
MiMo WebSocket streaming or speaker identification. Default prompts are retained.

For beta/production, declare `self_hosted_inference.<stage>: mimo-cn` in the
brand manifest. Eddy selects both stages. The shared renderer freezes this
choice into backend, Web and native profiles. The production Compose wrapper
derives the model services from that same selection, keeps local Embedding,
and requires `MIMO_API_KEY` in the private host environment. It removes unused
local LLM services and the speech model mount before Compose interpolation.

Server CD verifies public streamed chat and persisted history, then sends a
synthetic TTS recording through ASR and requires recognition of its work-notes
phrase. It also executes the admitted Embedding driver inside the accepted
backend image before advancing the release pointer. These checks do not claim
speaker-identification or realtime multimodal relay coverage. Historical relay
environment variables have no current Server consumer and are not startup
requirements.

MiMo selection does not qualify a Cloudflare deployment or the historical
zero-vendor cutover plan. The repository runbook `deploy/self-host/mimo-local.md`
documents credentials, boundaries and official API references.
