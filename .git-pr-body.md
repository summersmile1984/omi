The three shim files were merged so that upstream's new logic and the fork's
hooks both survive, with upstream's guard first in each case:

- `stt_provider_policy.py` — upstream added the `soniox` provider; the fork's
  `sensevoice` / `mimo` / `moss` sit alongside it in all three tables.
- `streaming.py` — upstream added `if provider_for_model_token(model) in exclude:
  continue` to the selection loop. It is placed **before** the fork's
  sensevoice/mimo dispatch, so fork providers also honour mid-session failover
  exclusion instead of being able to reselect a provider that just failed.
- `cloud_tasks.py` — upstream added a payload-schema assertion and backfill-lane
  routing. The schema assertion runs **before** the fork's Redis short-circuit,
  so a malformed payload is rejected on the self-hosted queue too.

The fork's hook footprint in those three files is unchanged by the merge
(`+31/-1`, `+15/-0`, `+26/-0` — identical to pre-merge), i.e. every upstream
change was taken and no fork behavior was dropped.
