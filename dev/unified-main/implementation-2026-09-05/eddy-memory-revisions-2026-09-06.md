# Cloudflare 记忆版本与索引任务的原子提交

基线 `6661799f59`，分支 `codex/unified-delivery`。这是 CF-4 记忆历史/撤销
的前置写入边界，不是这两个路由或整个生产部署的完成声明。

## 发现与实现

原生记忆写入没有可靠地同时保存向量 outbox；MCP、开发者和 X 各自用
秒级 `updated_at` 写索引版本。两次同秒编辑无法区分，嵌入计算期间的
新内容还可能被旧任务当作已经处理。录音级联删除也有一个动态调用的
旧 outbox 写入口，完整组件测试捕获了它。

Migration 0162 为现有 `item_revision` 建立数据库内的单调推进所有者。
创建、交互/生命周期更新和硬删除都在同一事务保存相应向量任务；保存
任务失败会回滚业务修改。旧索引和已有待处理时间戳在升级时被单调重置
到新版本之前。重新创建仍有待删除任务的身份时，新版本高于旧任务。
正在删除的账户留给既有清除所有者，迁移与清除期间不重建 outbox。

原生、MCP、开发者、X 和级联删除统一由 D1 触发器产生记忆索引任务。
旧应用层 helper 明确拒绝再写 memory outbox，其余数据类型保持原入口。
既有 MCP/开发者队列通知仍在事务提交后发送；原生路径的 durable outbox
由既有定时 reconciliation 消费。

`cf_memory_projection_sources` 视图统一索引准入条件：生命周期、锁、
账户代次、过期和受限标签。未评价的 NULL 不等于明确拒绝。Jobs 从该
视图读取实际 `item_revision` 并按这一版本确认完成，保留嵌入期间新写入
的任务。由于过期等原因需要撤销的 upsert 也按原任务身份完成清理。
提供方故障发生在业务提交之后时，仍保留可重试 outbox。

Failure-Class: FC-split-mutation-authority

该失败类的现有合并实例为 PR #9365、#9597。本次复用单一写入所有者
规则，防护是共享 D1 写入原语和行为回归，不另加静态源码检查器。

## 验证

- Core：`uvx uv==0.12.3 run pytest -q`，最终 **503 passed**，一项既有
  Starlette/AnyIO 弃用提示。新增五项完整迁移链回归覆盖同秒编辑、outbox
  失败回滚、锁/解锁/删除、待删除身份重建及有旧版本/删除围栏的升级。
  原有晚到锁测试改为比较外部加锁动作完成后的整行和副作用快照，避免
  把加锁自身应产生的新修订误当成被拒请求的写入。
- 私有复现实验仅撤去新投影触发器，原生同秒编辑和投影失败回滚两个
  回归均失败，证明旧写入没有这些保证。该实验不进入运行器或仓库。
- Cloudflare `npm test`：**111 files / 886 passed**。新增向量工作器
  回归在实际 SQL 写入和受控 AI 接缝中制造同秒编辑竞争，确认新任务
  保留并在下一轮处理；另验证未评价记忆可索引、受限源被撤销。
  `npm run typecheck` 通过。
- SQLite 工作器测试原先使用显式时间 100/200/300；现在把 D1 触发器的
  `unixepoch()` 也接到受控时钟。级联删除回归改用完整 App 迁移链，
  其余只测音频元数据的最小夹具保持原范围。这些是夹具与实际存储契约
  的对齐，没有把失败状态改成可接受结果。
- 新建本地 workerd 环境 `memory-revision-cf-20260906-b`：公共核心 HTTP
  **13/13**，录音/导出/隐私 **15/15**。新增场景通过真实公开注册和
  WebSocket PCM 录音，等待实际 Queue 完成记忆/任务提取，再执行级联
  删除，验证关联记录消失及另一账户录音保留。完整账户删除仍用独立的
  有录音、记忆、任务和附件的账户验证，两个被删除账户 App/Auth/R2
  逻辑残留均为零。没有植入业务数据库、缩短清除延迟或手动运行消费者。
- 实测使用正常编译的 Worker、完整 D1 迁移、Auth/Queue/R2。模型 IO 仍
  受控，不代表模型质量或 hosted Vectorize 清除。运行结束后自有进程
  正常清理。之后只更新了测试夹具/文档并撤回一处无关格式变化；运行时
  业务逻辑未再改动。

默认提示词、工具描述、模型配置和上游文件未修改。Server OS 运行镜像
也未修改；上一轮共用 HTTP 核心的 13/13 证据仍在，未重复声称本轮又
执行了 Server 端的完整业务矩阵。

## 仍需完成

外部向量仍使用稳定对象 ID。多工作器逆序完成时的发布围栏、按版本
区分向量对象、写入/清除期间的残留跟踪，以及准确的 hydration 新鲜度
检查和诊断仍需实现验证。本轮不能用单个嵌入期间编辑测试覆盖这些
并发场景。历史/撤销还需要追加版本链、精确幂等、当前尾版本的隐私
判断。CF-4 清单保持 **583 staging-owned / 36 blocked**，两个完整发布
qualifier 仍未完成；没有发布生产 Worker。
