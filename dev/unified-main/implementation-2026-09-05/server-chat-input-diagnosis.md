# Server 聊天：输入体积与真实模型超时

9 月 6 日，在 `9b7e48dca2` 的应用镜像及原有 d 轮数据上，新建独立聊天会话，
通过真实 Auth 换票和公开 `/v2/messages` 询问已保存的个人偏好。该会话没有
之前失败回复的历史。约 0.4 秒收到准备事件，300.3 秒收到错误及结束帧；
不是成功答案，也没有记忆工具执行事件。

同一请求的 Ollama 日志显示输入约 7,700 个模型原生 token。超时前仍在
prefill，已处理 5,504 个 token，耗时 288.53 秒，尚未生成回答。故本轮
不能归因于记忆库为空、检索工具返回空结果，或客户端漏显示答案。

随后在同一个实际应用容器内执行上游提示词、用户上下文、工具集合及 fork
模型适配的组装路径，在模型调用边界捕获请求，不执行推理、不写聊天记录。
这是组装诊断，不代替公开 HTTP 的业务验收。捕获结果如下：

| 部分 | 实际大小 |
| --- | ---: |
| 系统提示词 | 13,509 字符 |
| 单条用户消息，含诊断的固定时间块 | 117 字符 |
| 8 个工具 schema 的 JSON 合计 | 19,402 bytes |
| 其中，工具说明文字合计 | 15,089 字符 |

8 个已准入工具均存在：会话读取/搜索、记忆读取/搜索、任务读取/创建/更新、
偏好保存。未发现 fork 丢失工具 schema。系统提示词仍带上游的通知管理和
URL 获取说明，虽然这些工具已被当前部署能力过滤；末尾另有能力限制说明。
大量工具示例与系统提示词重复。这里的“输入 token”由模型运行时日志报告，
不是把 GPT-4 的 tiktoken 估算当成 Qwen 的计数。

私有证据目录为 `/Users/macstudio/.codex/eddy-production/`：
`server-retrieval-new-session-20260906-a.log`、
`server-prompt-capture-20260906-a.log`、
`server-prompt-payload-20260906-a.json`。账户与问题均属于隔离验收夹具。

对照仅缩短工具说明，保留同一模型、完整系统提示词、8 个工具及其原始
参数 schema。结果为 274.69 秒结束，模型原生计数 5,248 个输入 token、
10 个输出 token，没有工具调用，回答照抄提示词中的占位示例
`I don't have anything about [person].`。该对照未执行工具，也未通过公开
HTTP 路径，不是修复成功或发布资格。私有证据为
`server-compact-tools-diagnostic-20260906-a.log` 和
`server-prompt-compact-tools-diagnostic-20260906-a.json`。

用户随后明确要求不调整默认提示词。刚开始编写的默认提示词和工具描述
改动已全部撤回；运行代码、测试文件、启动配置均恢复至 `9b7e48dca2`，
未构建或运行这些改动。后续验收保持默认提示词和工具描述，检查模型、
运行性能及适配配置，不能通过修改提示词获得通过结果。

上述 AI 功能确实运行在本机 Docker：SenseVoice/Kokoro 在后端容器内，
Qwen3 1.7B 与 BGE-M3 分别在 Ollama 容器。LLM 的实际 CPU 限额为 4 核、
内存限额 4 GiB。此前 Cloudflare 本地 workerd 业务夹具的 ASR/LLM 使用
受控推理响应，不能代替真实 Workers AI。Cloudflare 生产发布和 macOS
生产联通仍未完成。
